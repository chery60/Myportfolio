Redesinging the assign flow in assignments module

Introduction

The assignments module in Toddle’s educator platform is one of the most frequently used. It lets teachers assign tasks, learning experiences, worksheets, and assessments. Currently, users can assign tasks, set submission deadlines, schedule when the assignment becomes visible to students, and close submissions after the due date. Teachers can also set specific times for these actions.

Identification of Problem

Inflexible assignment locking:

Right now, assignments are automatically locked once the due date passes, with no option to set a different close date. This prevents late submissions, putting us at a disadvantage compared to competitors who allow extended deadlines.

Confusing user interface

The current interface for scheduling and assigning tasks is not very intuitive, leading to teacher confusion. Due date and scheduled date fields lack clear context or explanations, making it hard for users to understand how these settings affect assignment management.

Limited control over assignment visibility

At the moment, assignments can either be scheduled for future release or published immediately. However, a program-level setting controls visibility for all scheduled assignments, meaning that if it’s enabled, everything becomes visible to students. Teachers can’t choose to show some tasks while hiding others, like assessments. Many competitors offer more flexible options, allowing teachers to publish or unpublish individual assignments, which better supports different teaching approaches.

User Goals

Our goal is to improve the task assignment process by making due dates, schedule dates, and close dates easier to manage and understand. We’ll simplify the terms used and make it clearer for both students and teachers to track and handle assignments.

User journey

The assignment process is broken down into three phases: actions taken before the task is assigned, during the task, and after the task is completed.

Permission configuration

The assignments module is set up to handle past, present, and future tasks, which affects what students, parents, and teachers can see across the educator, student, and family platforms. To manage this, we needed to clearly define the visibility permissions.

Time series analysis

Once we set the visibility permissions, the next step was to define the time-based analysis. This included tracking assignments through three main states (“In drafts,” “Assigned,” “Completed”) across four phases: “Before the assignment start date,” “After the start date but before the due date,” “After the due date but before the close date,” and “After the close date.”

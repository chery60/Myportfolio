## Introduction

Oracle’s Food and Beverage Global Business Unit offers several enterprise software solutions, including the Enterprise Management Console (EMC), Backoffice, Point of Sale (POS), and Kitchen Display System (KDS). Each of these had its own user management system, which made it challenging to manage users across multiple products. To solve this, the team decided to create a unified user management system to streamline user management across all the platforms.

## Back Story

The team has decided to build a single platform to fully maintain Back Office, Point of Sale (POS), Enterprise Management Console (EMC) users, and their access. The entire back office software is built on a different architecture (OJET-6). The Enterprise Management Console software was upgraded to a new OJET-12 which supported a complete stack of components to make for a new redwood design system.

## Problem Statement (‘How might we’ statement)

How might we help an administrator add and manage user access of all employees across the Back Office, EMC, and POS from a single unified platform?

## Identification of problems

### Know Problems:

1. Building a Unified platform supporting both the architectures (i.e. OJET 6 and OJET 12 level architectural components should be collaborated)<br />
2. Unifying the data flows(i.e. defining the data points and saving triggers) for both the respective product's onboarding journeys was different and the data got saved to their respective database tables.<br />
3. Filtering of Users as the users for both the plates will be migrated to a new unified platform<br />
4. Building two different workflows one which supports labor management products and one which doesn’t support<br />
5. Managing the access of common employees present on both platforms which includes deletion of users, and managing permission among zones, revenue centers, and locations.

### Unknown Problems

1. Improving the information architecture. To build the right workflows<br />
2. Improving the overall product experience by handling the component mismatch and screen responsiveness.

## Approach to Problems

### Know Problems:

Building a Unified platform supporting both the architectures (i.e. OJET 6 and OJET 12 level architectural components should be collaborated ) —<br />
1. The entire product of the back office was built on OJET 6. so uplifting the entire product to OJET 12 to build the product using the new redwood design system would take a lot of time. so the team has decided to build the user management using the ALTA SC component library (an intermediate component stack used to upgrade the very old Oracle products before the full all-new redwood design system build)<br />
2. Made a list of all the components that could support the framework and build a low-fidelity workflow to conduct the first-level user interviews.<br />
Unifying the data flows(i.e. defining the data points and saving triggers) for both the respective product onboarding journeys was different and the data got saved to their respective database tables —<br />
1. The process of user creation and copying users from the platforms was different for the two respective products so built a UI that supported setting the save triggers and fetching data in the workflow.<br />
2. After talking to the stakeholders and understanding the current system built the shape of the data so that I could use that data to build the layout.

## Filtering of Users as the users for both the plates will be migrated to a new unified platform

1. As the user persona was an administrator based on the persona I designed the table and added an advanced search bar using which the administrator could easily filter out the users.<br />
2. I talked to the users and understood what columns they would require which they came across on the landing page.
